# Contribution Protocol

What you must update when you change this repository. Applies to humans and
agents equally.

---

## The rule

> **If you changed code that a `.brain` document names in its `sources:`, you
> update that document in the same change.**

Not later. This repo already has direct evidence of what happens when it's
later instead: `docs/ai-connector/PROGRAM-PLAN.md` still stated the
`mcp_widgets.kind` CHECK as two-valued after migration 149 widened it to five —
a doc that fell behind a schema change nobody circled back to fix.

There is no CI to enforce this yet (no `.github/`, no `brain verify` gate). Run
it yourself:

```bash
node agent-brain-tool/bin/brain verify . --strict
```

## By change type

| You changed | Update |
|---|---|
| Behavior inside a domain (Deen, Fitness, Self-Mastery, Work/Co-op, Business/Lock-In, School, Home, Evening-Close, Distractions/Check-ins, Calendar, Insights, MCP connector, Widgets, Settings) | `.brain/domains/<domain>.md` |
| A migration that changes a table's shape or a CHECK constraint | the owning domain doc, and `.brain/memory/known-issues.md` if it closes or opens a known gap |
| A dependency between domains/services | `.brain/architecture/dependency-graph.md` |
| How data moves (e.g. legacy vs. domains-mode nav, MCP write path) | `.brain/architecture/data-flows.md` |
| Made a non-obvious technical choice (a ruling like the missed-Lock-In-hours reversal) | `.brain/memory/decisions.md` |
| Hit a trap others will hit | `.brain/memory/known-issues.md` |
| Tried something that failed | `.brain/memory/lessons.md` |
| Started/finished significant work | `.brain/memory/active-work.md` |
| A script, npm command, or integration | `.brain/tooling/registry.md` or `.brain/tooling/integrations.md` |
| Ownership or a role | `.brain/governance/ownership.md` |

## For agents specifically

**At session start:** read root `CLAUDE.md`, then only what the routing table
points you at. Do not crawl the repository — `REPOSITORY_MAP.md` and
`context/ARCHITECTURE.md` exist precisely so you don't have to.

**During work:** when a `.brain` summary contradicts the code, the code is
right. Fix the summary and note the correction. A silently-wrong summary is
worse than a missing one.

**At session end, record:**
- Decisions with reasoning → `.brain/memory/decisions.md`
- Traps hit → `.brain/memory/known-issues.md`
- Dead ends → `.brain/memory/lessons.md` (the highest-value one — this repo's
  own history shows why: the dead-code sweep in
  `docs/superpowers/notes/2026-08-18-orphaned-code.md` only became reliable
  after two false-negative classes and one false-positive class were found the
  hard way. That method note is exactly what `.brain/memory/lessons.md` is for.)

**Never:** delete a `.brain` document without archiving it · edit
`.brain/indexes/*` by hand (generated by `brain index`) · move or rename a file
under `docs/superpowers/` without checking whether live code or a migration
header cites it by name first (several do — see
`gov.knowledge-lifecycle`'s "What `.brain` does not replace") · exceed a token
budget without recording the exception.

## Verification gate

No CI exists in this repo today. Until one is added (an operator decision, not
this install's to make — see the Agent-Brain project's tooling-adoption playbook (not installed in
Agent-Brain project), verification is manual:

```bash
node agent-brain-tool/bin/brain verify . --strict
node agent-brain-tool/bin/brain index .   # regenerate indexes first if stale
```

If a GitHub Actions workflow is ever added to this repo, this should be a
required check — but wiring that in is an explicit operator decision, not
something to add silently.
